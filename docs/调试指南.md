# 调试与排错指南 (Debugging Guide)

当脚本不仅仅是“不工作”，而是“点歪了”或“没反应”时，请按照本指南进行排查。

## 1. 开启上帝视角 (Debug Mode)

在 `g_debugConfig` 中将 `debugMode` 设置为 `true`。

### 预期行为
1.  **声音反馈**:
    *   启动并扫描窗口时，会听到急促的 `Beep` 声。
    *   每完成一个步骤，会有不同的提示音。
2.  **视觉反馈 (Visual Boxes)**:
    *   脚本在屏幕上绘制半透明的矩形框。
    *   **红色框**: 表示脚本正在搜索的大概范围（Search Scope）。
    *   **蓝色框**: 表示脚本基于颜色收缩后的有效区域（Data Region）。
    *   **绿色框**: 表示最终确定的交互点或结果区域。

## 2. 常见问题排查

### 情况 A: 连窗口都找不到
*   **现象**: 脚本启动后直接退出或报错，没有任何反应。
*   **检查**:
    *   `g_windowConfig["targetAppName"]`: 确保这个字符串能匹配到你的窗口标题。建议使用 `ahk_exe process.exe` 格式。
    *   `minWindowWidth`: 你的窗口是不是太小了？如果窗口被缩放得很小，可能会被过滤器忽略。

### 情况 B: 红色框位置不对
*   **现象**: 红色框（搜索范围）出现在了屏幕的其他地方，或者偏移了。
*   **检查**:
    *   **DPI 缩放**: Windows 的“缩放与布局”设置是否为 100%？如果不是，AHK 获取的坐标可能偏移。
    *   **坐标模式**: 确认脚本是否正确识别了 Client 区（不含标题栏）和 Screen 区（全屏）。框架内置了 `SafeActivateWindow` 来自动处理，但如果目标应用是非标准窗口，可能需要调整 `yMinOffset`。

### 情况 C: 只有红色框，没有蓝色/绿色框
*   **现象**: 脚本圈出了范围，但随即报错“找不到颜色”或直接跳过。
*   **检查**:
    *   **颜色值 (`g_colorConfig`)**: 取色是否准确？甚至差 1-2 个色值都可能导致失败。建议增大 `g_debugConfig` 中的 `colorOffset` (容差)。
    *   **遮挡**: 目标区域是否被弹窗、鼠标指针或其他浮层遮挡了？

### 情况 D: 蓝色框一直在抖动 (Loop Break Timeout)
*   **现象**: 看到蓝色框忽大忽小，最后脚本报错超时。
*   **原因**: 视觉定位算法试图通过迭代收缩找到一个“稳定”的区域，但如果界面上有动态光效（呼吸灯）、滚动的文字，会导致区域边界无法稳定。
*   **解决**:
    *   增大 `LoopBreakException` 的容差。
    *   在 `g_splitConfig` 中调整模数，避开动态区域。

## 3. 日志分析

如果是 **调试版.ahk**，请检查脚本同目录下的 `ahk_experiment.log`。
日志会详细记录每一次 `OS_PixelSearch` 的调用参数和返回结果。

```log
2023-10-27 10:00:01 OS_PixelSearch x1:100 y1:200 x2:500 y2:600 Color:0xFF0000 -> Found: 150, 250
```

如果看到连续大量的 `Found` 坐标在剧烈跳变，说明颜色定位逻辑不稳定。
