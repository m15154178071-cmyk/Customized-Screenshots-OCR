# 参数配置指南 (Configuration Guide)

由 `Customized-Screenshots-OCR` 的高度灵活性决定，其配置主要集中在 `Global Config` 区域。正确配置这些参数是脚本成功运行的关键。

## 1. 核心配置文件

所有配置均位于脚本文件（如 `工程版.ahk`）的头部（约第 300 行起）。

### 1.1 程序启动配置 (`g_programConfig`)
用于定义需要脚本自动启动和管理的外部应用程序。

```autohotkey
global g_programConfig := Map(
    ; 格式: "描述键名", ["可执行文件绝对路径", "启动参数(无参数留空)", "窗口标题标识(可选)"]
    ; ⚠️ 注意：以下OCR与截图工具配置为未来扩展预留，当前版本脚本逻辑中尚未实际调用
    "OCR工具", ["D:\Tools\Umi-OCR\Umi-OCR.exe", "", "Umi-OCR"],
    "三方截图工具", ["C:\Program Files\ShareX\ShareX.exe", "-s", "ShareX"]
)
```

### 1.2 窗口与布局配置 (`g_windowConfig`)
控制目标窗口的识别尺寸和排列规则。

*   **`targetAppName`**: 目标程序的窗口标题或 ahk_class (例如 `"ahk_exe notepad.exe"`).
*   **`minWindowWidth` / `minWindowHeight`**: 只有大于此尺寸的窗口才会被识别和排列（过滤掉隐藏窗口或弹窗）。
*   **`windowArrangementXMultiplier`**: 窗口排列时的横向间距系数。

### 1.3 视觉分割配置 (`g_splitConfig`) **[高难度]**
这是本框架最抽象的部分，决定了如何将屏幕区域切割为网格。

*   **`modMin` (基础模数)**: 整个网格系统的最小单位（像素）。建议设置为目标UI中最小可点击元素的尺寸的一半。
*   **`xCoarseAndFine` / `yCoarseAndFine`**: 粗细分割比例。
    *   例如 `xModNum = modMin * xCoarseAndFine`。
    *   这个参数决定了“大格子”的大小。
*   **`xDivisions` / `yDivisions`**: 屏幕被划分的份数。

> **💡 配置技巧**:
> 1. 先截图你的目标窗口。
> 2. 在画图工具中打开。
> 3. 打开网格线。
 > 4. 尝试找到一个能大致对齐所有按钮/文本框边缘的网格大小（比如 20px）。
 > 5. 但 `modMin` 实际应设置为“小于等于你选定的像素值且最接近的2的幂次方”，例如你测得20，则应设置为16（2的4次方），而不是20。
 >    实际上，**你只需预估一个大致值，脚本会自动计算并取最接近的2的幂，无需手动换算。**

### 1.4 颜色特征配置 (`g_colorConfig`)
定义脚本“眼中”的颜色。

```autohotkey
global g_colorConfig := Map(
    ; 建议使用 RGB 0xRRGGBB 格式
    "DataRed", "0xFF4444",   ; 数据区域的红色文字
    "ButtonBlue", "0x0088FF" ; 确认按钮的蓝色背景
)
```


## 2. 颜色容差与映射

### 2.1 g_colorMap 的作用与用法

**`g_colorMap`** 是本框架颜色配置的“中间层”，用于将业务逻辑中出现的“中文语义名称”映射到实际的颜色配置键名（即 `g_colorConfig` 的 key）。

#### 主要作用：
1. **业务解耦**：让业务逻辑代码只关心“语义”，而不关心底层颜色变量名。
2. **便于维护**：当 UI 主题变更或颜色方案调整时，只需修改 `g_colorConfig` 和 `g_colorMap`，无需修改主流程代码。
3. **多语言/多主题适配**：理论上可通过切换 `g_colorMap` 实现不同语言或主题下的颜色适配。

#### 典型用法：

```autohotkey
global g_colorConfig := Map(
    "DataRed", "0xFF4444",
    "ButtonBlue", "0x0088FF"
)
global g_colorMap := Map(
    "核心数据红", "DataRed",
    "确认按钮蓝", "ButtonBlue"
)
```

在业务逻辑中：

```autohotkey
targetColor := g_colorConfig[g_colorMap["核心数据红"]]
```

这样，若 UI 主题变更，只需在 `g_colorConfig` 或 `g_colorMap` 中调整，无需动主流程。

#### 配置建议：
* 业务逻辑中尽量只出现“中文语义名”，如“核心数据红”、“确认按钮蓝”。
* `g_colorMap` 的 key 用中文，value 用 `g_colorConfig` 的 key。
* 颜色值统一用 RGB 0xRRGGBB 格式。


## 3. 调试配置 (`g_debugConfig`)

建议在初次配置时开启调试模式：

```autohotkey
global g_debugConfig := Map(
    "debugMode", true,           ; 开启后会有弹窗和声音提示
    "defaultTransparent", 150,   ; 调试框透明度 (0-255)
    "matchColor", "0x00FF00"     ; 匹配成功时显示的框颜色
)
```

## 4. 通用（common）核心类功能简介

以下为所有主流代码版本（工程版/教学版/调试版）均包含的基础类功能，属于本框架的“公共能力”：

### WindowArranger
自动查找、激活并排列所有目标应用窗口，支持多窗口批量处理。

### RectangleInfo
负责将指定区域按 X/Y 方向分割为网格，生成所有子区域坐标。

### CoordinateMapping
实现点到网格单元的映射，支持“给定坐标，判断属于哪个格子”。

### LoopBreakException
用于判断区域收缩/定位过程是否“收敛”或“稳定”，防止死循环。

### WindowColorRegion
用于调试时在屏幕上高亮显示指定区域，支持半透明彩色矩形。
